# scrolly-site — source of truth for the scrollyseo.com public pages (2026-09-21 redesign)

Implements the approved `Scrolly Homepage (2).html` mockup (Archivo / Public Sans / Caveat Brush; black `#000`, orange `#ff6338`, cream `#fbf8f3`, teal `#94ece1`, lavender `#c1aefc`, purple `#735cff`, peach `#ffb38f`) on the live WordPress site and carries it across the rest of the public site. The mockup itself is kept as `homepage-reference.template.html`; its embedded images were extracted to `assets/` and uploaded to the WP media library (`media-map.json` maps file → media id/URL).

**Design note:** for the public site this supersedes the palette in `Scrolly Organic Engine/brand/visual-system.md` (which assumed teal `$1K` / TBD `$10K` / gold `$24K` and a navy/Poppins look — now dead). The approved mockup uses `$1K` teal, `$10K` lavender, `$24K` peach. The provisional-logo caveat in that doc still applies to the *Club app*, not this site.

## Layout
| File | Purpose |
|---|---|
| `shared.css` | The design system. Everything scoped under `.scx` so nothing leaks into WooCommerce/theme UI. |
| `lib.mjs` | Page components (product cards, rails, CTAs) + `shell()` / `pageStyle()`. Header/footer are NOT here — see `chrome/`. |
| `pages/home.mjs` | Homepage (page 161). |
| `pages/offers.mjs` | `$1K/$10K/$24K` Club + Challenge pages (291, 303–307) and `/clubs/` (314), `/challenges/` (315). |
| `pages/catalog.mjs` | Digital Products (312), Merch/Scrolly Shop (313), SEO Tools (316). |
| `pages/legacy.mjs` | Existing pages whose content is preserved but re-chromed: cart 6, checkout 7, my-account 8, about 119, contact 124, accessibility 171, privacy 64, terms 65, refund 66, implementation 263, SEO Site Audit 16, Shopify workbook 50, Pinterest workbook 71. Built from `../backups/2026-09-21-pre-redesign`, so it is idempotent. |
| `build.mjs` | `node build.mjs [module…]` → `dist/<key>.html` (+ `.preview.html`). Fails the build if CSS text leaks outside `<style>`. |
| `publish.mjs` | `node publish.mjs <key…>` → POSTs `dist/<key>.html` to the mapped WP page via REST (Application Password from `automation/.env`). |
| `menus.mjs` | One-off: aligned the theme's real WP menus with the new nav. |
| `fix-product-descriptions.mjs` | One-off: removed a stray `<style>` block from the WooCommerce descriptions of products 58/69/24 (it printed as text in the block cart). |
| `linkcheck.mjs`, `page-audit.js`, `contrast-audit.js` | Verification helpers (HTTP link/image check; browser-console layout + contrast audits). |

`dist/` is generated and git-ignored. Preview locally with the `website` launch config → `http://localhost:8934/scrolly-site/dist/<key>.preview.html`.

## Publishing
```
node build.mjs && node publish.mjs home clubs challenges 1k-club …
```
Pages are single `wp:html` blocks (no Elementor). Header + footer come from the global snippet (see round 2 below); the theme header/footer are hidden by the chrome CSS, so there are never two menus.

## Rollback
`website/backups/2026-09-21-pre-redesign/` holds the full pre-change REST dump of every page (`pages/<id>-<slug>.json`, includes raw content + `_elementor_data`), all 28 menu items, menus, site settings, and products 24/58/69/279/280. To restore a page: POST its `content.raw` back to `/wp/v2/pages/<id>` (and, for Elementor pages, `meta._elementor_edit_mode` back to `builder`).

## Known limits (see the session report in `current-state.md`)
- Single product pages (`/product/*`), the WooCommerce archive `/shop/`, and 404s are rendered by the theme, not by page content, so they still show the *theme* header/footer (whose real menus now mirror the new nav). Unifying them needs one global CSS/HTML injection (WPCode / theme) which requires a wp-admin session.
- Elementor-built pages (16, 50, 71, 119, 124, 263) were flipped to plain `wp:html` (their Elementor data is intact but no longer rendered). Opening them in Elementor and saving will revert them to the old layout.
- Fonts load from Google Fonts (same families/weights as the mockup's embedded files), not self-hosted.

## Update 2026-09-21 (round 2) — global chrome, black brand, real $1K offer
- **Header/footer are no longer in page content.** One WPCode PHP snippet (`chrome/wpcode-snippet.php`, generated by `node chrome/install-chrome.mjs`) prints them on every front-end page (incl. product pages, /shop/, 404). Header nav + drawer are built from the WP **Main Menu**; footer links from the **Footer Menu**. Menu items with CSS class `scx-drawer-only` show only in the drawer. Chrome CSS/JS/logo SVG live in three private pages (ids in `chrome/ids.json`); re-run `install-chrome.mjs` to push changes without re-pasting the snippet.
- No per-page/active-state header customization exists any more. Footer = logo + Footer-Menu links + "© year Scrolly. Earn Your Stripes."
- Brand: navy is gone; black is `#000` (`--black`). Old indigo/violet palette and Manrope/Inter are remapped/overridden on the long sales pages.
- Logo: `assets/scrolly-wordmark.svg` is a vector recreation in Archivo (wght 900, wdth 78, tracking −0.03em) because only a 126px raster existed — swap in the original vector if one exists.
- `status.mjs` checks WooCommerce at build time: purchase CTAs (`/?add-to-cart=<id>`) render only for published, in-stock products (279 $1K Club). `1k-challenge` shows "Request launch news" until product 280 is published; then rebuild + publish.
